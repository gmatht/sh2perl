# Status of the bash-vs-Perl differential gate (tests/bash-parity.sh).
#
# The gate's contract: render with the SHIPPED CLI path (`perl_backend
# --fixed`), require `perl -w -c` to accept the render and report no
# `Useless use`/masked-redeclaration warning, then run bash and the Perl in
# the SAME absolute working directory (wiped between runs) and compare stdout,
# exit status, and — for tests/loop-status, tests/status and tests/tier1 —
# stderr. `$0` is set identically for both (`$0 = <source path>`) and both
# sides' paths are normalized to `<script>` before comparing, so invocation
# metadata does not masquerade as behaviour.
#
# `bash tests/bash-parity.sh --all` sweep, 2026-11-28, shipped CLI, default
# stack: 556 of 556 `examples/*.sh` match bash on stdout and exit status with
# warning-free `perl -w -c`. The five `parse-error-*` fixtures are expected to
# be REJECTED (exit 2) and are asserted as such, not rendered.
#
# Nothing is excluded from the `--all` comparison. The list below is empty by
# construction: every corpus example is either compared and matching, or a
# parse-error fixture that must not render.

# ── Brace expansion: variable adjacent to a brace (NOT fixed) ────────────
#
# bash brace-expands the RAW word text before any parameter expansion, so a
# variable butted against a brace is part of the same word in a way this
# parser cannot represent: `BraceExpansion.prefix/suffix` are static Strings,
# so `${x}{1..2}` reaches the IR as two independent words. Measured against
# bash (x=VAR):
#
#   ${x}{1..2}   bash: VAR1 VAR2          perl: VAR 1 2
#   p{1..2}${x}q bash: p1VARq p2VARq      perl: p1 p2 VARq
#   ${x}{a..c}   bash: VARa VARb VARc     perl: VAR a b c
#   $x{1,2}      bash: (empty: `$x1 $x2`) perl: VAR 1 2
#
# Fixing this means either a frontend brace pass over raw word text or a
# dynamic prefix/suffix on the brace node (AST + shIR + every backend). It is
# a silent wrong-output class in ordinary scripts (`cp $d/{a,b} dst`), so it
# is listed here rather than left unstated.
#
