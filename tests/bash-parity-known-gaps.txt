# Status of the bash-vs-Perl differential gate (tests/bash-parity.sh).
#
# The gate's contract: render with the SHIPPED CLI path (`perl_backend
# --fixed`), require `perl -w -c` to accept the render with no warning at all,
# then run bash and the Perl in the SAME absolute working directory (wiped
# between runs) and compare STDOUT, STDERR and EXIT STATUS byte-for-byte for
# every swept fixture. `$0` is set identically for both (`$0 = <source path>`)
# and both sides' paths are normalized to `<script>` before comparing, so
# invocation metadata does not masquerade as behaviour; the `script: line N: `
# prefix of a diagnostic is dropped on both sides for the same reason, and the
# renderer's optional `sh2perl: uu-ffi ` notice is stripped.
#
# `bash tests/bash-parity.sh --all` (2026-11-29, shipped CLI, default stack)
# sweeps every one of the 556 `examples/*.sh`: 538 match bash on stdout, stderr
# and exit status (5 of them are parse-error fixtures, asserted to be REJECTED
# rather than rendered); 18 are the known divergences listed below, each with
# its reason (two of them are order-only, compared as a sorted multiset). Two
# consecutive sweeps report the same verdict for every example. Total diff count: 0. No fixture is skipped: every entry below is
# READ by the gate, reported as KNOWN with its reason, and shown in the
# summary. The ledger is validated in the other direction too — an entry whose
# fixture now matches bash, or that names a fixture which no longer exists,
# fails the gate as STALE.
#
# ── KNOWN DIVERGENCES (machine-read) ─────────────────────────────────────
#
# Format: one entry per line, tab separated, `<fixture without .sh><TAB>
# <reason>`. Lines beginning with `#` are documentation. The reason must say
# WHY the bytes differ; a fixture may not be added here to hide a wrong
# answer (stdout/status divergence would be a bug, not a wording difference) —
# every entry below is stderr-only and every one has bash's own output quoted
# in the prose further down.
#
# ── Concurrent writers: the ORDER is not bash's to promise ───────────────
#

# does not order it: `diff <(sort file1) <(sort file2) > f 2>&1` runs the two

# descriptor. A reason starting with `nondeterministic:` tells the gate to
# compare that fixture's stderr as a sorted multiset — the lines still have to
# match exactly, only their order is exempt.
#

#

# ── Redirection shapes the emitter does not lower yet ────────────────────
#
# Found while writing tests/tier1/redirect_forms.sh and
# tests/tier1/dup_stderr_to_stdout.sh. Neither is in the corpus, so the sweep
# cannot see them; they are recorded here because a fixture that pinned the
# current behaviour would bless a wrong answer.
#
#   exec 3> f4; echo three >&3; exec 3>&-; cat f4
#     bash:  three          rc=0
#     perl:  (nothing)      rc=0, plus `three: command not found` on stderr —
#            an arbitrary fd (`3>file`, `>&3`, `3>&-`) is not modelled, so the
#            word is dropped and the echo's argument list loses its redirect.
#
#   printf 'x\n' 1>&2
#     bash:  x on stderr
#     perl:  (nothing) — `1>&2` on a natively lowered printf loses the bytes
#            (the dup fix covers `2>&1` in the stderr position, not an
#            explicit stdout dup on a builtin that the renderer prints itself).
#
# Fixing either is emitter work (a general fd table / a stdout-dup arm for the
# native printf), tracked with the known divergences above rather than hidden
# inside a green fixture.
#
# ── Brace expansion: variable adjacent to a brace (FIXED) ────────────────
#
# bash brace-expands the RAW WORD TEXT before parameter expansion, so
# `${x}{1..2}` is one word per alternative (`${x}1`, `${x}2`). The AST cannot
# express that (`BraceExpansion.prefix/suffix` are static text), so
# `parser::words::splice_adjacent_brace_words` rewrites the SOURCE TEXT of a
# mixed word into the N ordinary words bash's expansion produces, then
# re-lexes. Measured against bash (x=VAR, y=YY), now identical:
#
#   ${x}{1..2}     → VAR1 VAR2
#   p{1..2}${x}q   → p1VARq p2VARq
#   ${x}{a..c}     → VARa VARb VARc
#   $x{1,2}        → nothing (`$x1`/`$x2` are unset: bash's TEXTUAL naming)
#   {a..c}${x}     → aVAR bVAR cVAR
#   ${x}{1..2}${y} → VAR1YY VAR2YY
#   x{1..2}y{3..4}z → x1y3z x1y4z x2y3z x2y4z
#   {a1..c3}${x}   → {a1..c3}VAR (literal group, concatenated)
#
# Standalone braces keep the AST path (a for-loop still iterates its range, and
# the 1024-item guard still applies); assignment words keep their braces
# (`v=${x}{1..2}` → `VAR{1..2}`, `w={a,b}` → `{a,b}`), and nothing is
# expanded inside `[[ … ]]`.
#
# Fixed alongside it: the Perl emitter's concat→interpolation pass printed
# `$x` unbraced in front of the next piece (`$x . "{a}"` → `"$x{a}"`, a hash
# element; `$x . "1"` → `"$x1"`, a different variable). It now emits `${x}`
# whenever the following text would extend the name.
#
# ── Command conditions in CONDITION position (FIXED) ────────────────────
#
# A command in condition position means "its exit status is 0". Test/native
# lowering already turned `[ … ]`, `[[ … ]]`, `-f`, arithmetic, `grep -q` and
# `cd` into Perl-native booleans; what had NO Perl expression form were
# `pipeline(…)` (`if echo hi | grep -q hi`) and `subshell(…)` (`if (exit 1)`).
# Both emitted calls to helpers that do not exist, so the whole program died
# with `Undefined subroutine &main::pipeline`.
#
# One seam now owns the rule (`ir::cond_expr_to_perl`, used by if/elsif/while/
# until/do-while/ternary and by `!`/`&&`/`||` operands):
#   * `pipeline(…)` runs its STATEMENT form inside `do { … }` and the branch
#     reads `$CHILD_ERROR`;
#   * `( … )` forks through the `__sh_subshell` helper (inline block could not
#     isolate `exit`, which ended the whole program);
#   * everything Perl-native is left untouched — never wrapped in an
#     exit-status convert.
# Pinned by tests/tier1/command_conditions.sh (39 branches: grep success/
# failure, negated, elsif chains, while/until over a changing command,
# pipelines, `&&`/`||` of commands, `[ ]`/`[[ ]]`, functions, `cd`, subshells,
# arithmetic ternaries).
#
# The uu-ffi fallback notice is now SILENT unless `SH2_UU_WARN=1`: a stderr
# line bash never prints is itself a divergence (tier1 fixtures compare it).
#
# ── `!` in two shapes (FIXED) ────────────────────────────────────────────
#
# Both residuals recorded here after the condition-position pass are gone:
#
#   1. `! ( … )` — the `!` arm skipped whitespace and then handed the paren
#      group to the simple-command parser, which flattened it into ONE exec
#      word: system('bash','-c','"exit 1"'), stderr `exit 1: command not
#      found`. src/parser/commands.rs now dispatches a leading `(` after `!`
#      to parse_subshell, so the group is an IrStmt::Subshell and the
#      condition seam forks it (no bash -c, no stderr).
#        bash: ok | ok           emitted: ok | ok
#   2. `! cmd && cmd` in STATEMENT position — the frontend built
#      `Not(And(cmd, cmd))`, which the shell-text rebuild then dropped.
#      `!` now negates the leftmost pipeline of the parsed chain
#      (negative_leftmost), so it is `And(Not(cmd), cmd)`.
#        bash: ran               emitted: ran
#
# Both shapes run in tests/tier1/builtin_status.sh (and the condition-position
# forms in tests/tier1/command_conditions.sh).
#
# ── Failed redirect: right status, different diagnostic prefix ────────────
#
# `$?` after a builtin whose REDIRECT fails matches bash exactly (1), but the
# message naming the file goes through the emitted shell's argv[0], so its
# prefix differs (bash names the script and the line; the emitted Perl names
# the Perl file and line 1):
#
#   echo hi > /no/such/dir/f 2>/dev/null; echo "rc=$?"
#     bash:  <script>.sh: line 4: /no/such/dir/f: No such file or directory
#            rc=1
#     perl:  x.pl: line 1: /no/such/dir/f: No such file or directory
#            rc=1
#
# Not fixable without teaching the renderer the original script path and the
# source line number; the STATUS (which is what a script branches on) matches.
# So the fixture covers echo/printf success and the failure paths of the other
# builtins, and this shape stays documented rather than in tier1 (tier1
# compares stderr byte for byte).
#
# ── Native builtin diagnostics: the failing path names the file differently ──
#
# A natively lowered `mkdir`/`rmdir` reports Perl's own errno text, which
# leaves out the operand bash echoes back. STDOUT and the EXIT STATUS match
# (the fixture covers those); only the diagnostic wording differs, and the
# gate strips the `line N:` prefix but not the operand. Exact inputs and
# both outputs:
#
#   mkdir d1
#   mkdir d1 && echo x
#     bash:  mkdir: d1: File exists          stdout: (none)  rc=1
#     perl:  mkdir: File exists              stdout: (none)  rc=1
#
#   rmdir absent || echo no
#     bash:  rmdir: absent: No such file or directory   stdout: no  rc=0
#     perl:  rmdir: No such file or directory           stdout: no  rc=0
#
# Fixing it means teaching the emitted builtin to print bash's message on the
# failure path (a second, bash-shaped message format next to Perl's `$!`).
# Every status, branch and stdout byte already matches, so this stays a
# documented wording difference rather than a tier1 (stderr byte-for-byte)
# fixture.
#

#
# A bare `export` assignment never reaches the shell scalar, so a later read
# is empty (and `perl -w` warns):
#
#   export e=hi; echo "[$e]"   bash: [hi]       perl: [] + uninitialized warning
#
# ── A missing input file: FIXED (bash's redirect diagnostic is emitted) ──
#
# examples/000__04h_complex_examples.sh calls a helper with a sibling script's
# name that only exists when the cwd IS examples/; the harness runs from a
# separate work dir, so bash's `< "$file"` redirect fails. The natively
# lowered `wc -c < FILE` / `cat < FILE` used to swallow the failure silently,
# so the emitted Perl printed nothing where bash complains. Both capabilities now print
# `<file>: <strerror>` on the failing branch, which is exactly what bash's
# diagnostic says once the `script: line N: ` prefix (normalised everywhere)
# is removed:
#
#   get_file_size 000__01_file_directory_operations.sh
#   (get_file_size does: local size=`wc -c < "$file"`)
#     bash:  000__04h_complex_examples.sh: line 43: 000__01_file_directory_operations.sh: No such file or directory
#     perl:  000__01_file_directory_operations.sh: No such file or directory
#     (both: stdout `File … has  bytes`, exit 0)
#
# With that fix `tests/renderer_behaviour.rs` compares stderr for EVERY corpus
# entry, with no exemption.
#
# ── Undef reads: `Use of uninitialized value …` (of the 52-example class) ──
#
# The one example the strict corpus had to drop rather than snapshot:
# examples/test-expression-backslash-continuation.sh reads `$FILE`, which is
# never assigned, in file tests and in a command substitution. bash treats an
# unset variable as the empty string; the render reads `$ENV{FILE}` directly,
# so Perl warns. STDOUT and exit match (both take the false branch); the
# warnings are the pre-existing undef class described above, not a new
# wrong answer, and fixing it means a project-wide "unset reads as empty"
# change. `077_backslash_continuation` + `021_ansi_quoting_escape` keep the
# corpus's continuation/quoting coverage with clean stderr.
#
#   FILE is unset; the example runs
#   [ \( ! -h "$FILE" -a -d "$FILE" \) -o \( -h "$FILE" -a "$(readlink "$FILE")" = "target" \) ]
#     bash:  (nothing on stderr)
#     perl:  Use of uninitialized value $argv[1] in open at x.pl line 63.
#            Use of uninitialized value in -l at x.pl line 74.
#            Use of uninitialized value in -d at x.pl line 74.
#            Use of uninitialized value in -l at x.pl line 74.
#
# ── Backtick bodies that cannot fold still hand their inner `$()` to a shell ──
#
# A backtick body with a native capture (`` `basename $(pwd)` ``) is computed
# in Perl and matches bash exactly. A body with a side effect that needs a
# SUBSHELL (`` `cd nested && basename $(pwd)` ``) keeps the outer shell-text
# form, so the inner substitution is emitted as `$('pwd')` INSIDE that text:
# still a real substitution the child evaluates (never a literal `$(`), and
# stdout/stderr/exit match bash — but the statement forks.
#
#   z=`cd nested && basename $(pwd)`
#     bash:  nested        (no fork: bash's backtick IS a subshell)
#     perl:  nested        (forked through __sh_pipe_capture)
#
# Nothing to fix in the escaping — `$(` is not swallowed — only the missing
# in-process subshell for a multi-command backtick body.
#
# ── One remaining builtin fork: a bare stdout redirect on `printf` ───────
#
# `printf … > FILE` still goes through the pipeline front end
# (`__sh_pipe_run(q{...})`) because the renderer has no in-process arm for a
# PRINTF whose output must be redirected. The behaviour is bash's (stdout,
# stderr, exit and `$?` all match); only the fork is left.
#
#   printf '%d\n' zz >/dev/null 2>/dev/null; echo "rc=$?"
#     bash:  (nothing)                       rc=1
#     perl:  (nothing)                       rc=1   (forked)
#
# `echo … > /dev/null` no longer forks (native_echo_devnull_discard: the
# output is discarded and the status is 0, which is exactly bash). A printf
# cannot take that shortcut — its numeric validation is what makes it FAIL —
# so it needs the full stdout-redirect machinery before the fork can go.
# Out of scope here: the compound/condition shapes this pass covered all run
# in process.
