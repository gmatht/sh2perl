# Proved here:
#   xargs_appends_the_input_word — the general agreement law: `echo CONTENT |
#     xargs echo A B` prints the command's words joined by single spaces with the
#     stdin word appended, exactly what `echo` writes for that argv. Stated on the
#     index-level join over `cmd.push(content)`, so the induction uses only the
#     `push` index axioms and concat associativity. (The first formulation
#     recursed with `skip` and needed `(ws + [c]).skip(1) == ws.skip(1) + [c]`,
#     which does not discharge here; the claim is the same, the formulation is
#     one the solver accepts.)
#   xargs_splits_on_whitespace — d-F4-1: `xargs` splits stdin on any run of
#     blanks and `echo` joins with ONE space; the fold copies the content, so a
#     double space survives the fold and collapses in the shell. Witness bytes.
#   xargs_empty_content_diverges — d-F4-2: `echo "" | xargs echo A` runs
#     `echo A`; the fold always inserts its own separator and emits `A `.
#   comm_12_one_common_line — a common line is pushed once and BOTH cursors
#     advance, which is what makes `comm -12` print a duplicate once.
#   diff_identical_inputs_are_silent — d-F4-5: on equal files the backtrack takes
#     only the prefix-match branch, so no hunk is opened and nothing is printed;
#     lemma_lcs_identical proves the DP diagonal is the file length, which is why
#     that branch is the one taken at every step.
#   sort_is_a_sorted_permutation — d-F4-3, the sorted-permutation law. The emitted
#     `@lines = sort @lines` (Perl's string `cmp` order) is modelled by
#     `pass_sort`/`ins` (insertion into a sorted prefix) on the pass side, and by
#     two functions written apart from it: `sorted` (no adjacent pair descends)
#     and `cnt`/`cnt_at` (how many copies of a line the list holds). The law says
#     `sorted(pass_sort(xs))` AND `forall x. cnt(x, pass_sort(xs)) == cnt(x, xs)`
#     — ordered and a permutation, i.e. no line lost, duplicated or invented.
#   ls_fallback_prints_iff_missing — d-F4-3, the `|| echo` status wiring. Pass
#     side: `scan_rc`, the emitted `for my $p (@paths)` accumulator (`$__ls_rc`
#     set to 2 when an operand is missing, then `$__rc = $__ls_rc ? 2 : 0`).
#     Semantic side: `any_missing`, its own OR-fold over the operand list, mapped
#     to a status by `ls_rc` and consumed by the emitted `if ($__rc) <built-in function print>`
#     guard `prints_echo`. Laws: `scan_rc(present,false,0) == ls_rc(present)` and
#     `prints_echo(scan_rc(present,false,0)) <==> any_missing(present,0)`.
#   sort_n_is_a_sorted_key_permutation — d-F4-3b, the `-n` law. Pass side:
#     `ins_key`/`pass_sort_n`, the numeric insertion sort (a line goes in before
#     the first line whose key is >= its own, which is what keeps ties in input
#     order — the emitted `sort_by` is stable). Semantic side, written apart:
#     `num_key` (a line's decimal value, 0 when it is not a number — the fold's
#     `parse::<f64>().unwrap_or(0.0)`), built from `is_int_lit`/`digits_acc`/
#     `digits_val`; `asc_key` (no adjacent pair has ascending keys); `cnt` (the
#     multiset model of §5). Law: `asc_key(pass_sort_n(xs))` AND
#     `forall x. cnt(x, pass_sort_n(xs)) == cnt(x, xs)` AND len preserved.
#   sort_r_is_a_descending_permutation — d-F4-3b, the `-r` law. `rev` is its own
#     `push` recursion modelling the emitted `lines.reverse()`; the semantic model
#     `desc_lex` says no adjacent pair ascends in byte order. Law:
#     `desc_lex(rev(pass_sort(xs)))`, `cnt` preserved, len preserved.
#   sort_nr_is_a_descending_key_permutation — d-F4-3b, the `-n -r` / `-nr` law:
#     `desc_key(rev(pass_sort_n(xs)))`, `cnt` preserved, len preserved.
#   decode_flags — the fold's flag loop modelled (`-n`, `-h`, `-r` and the glued
#     `-nr`/`-rn`/`-hr`/`-rh`), including its refusal (`None`) for any other word,
#     checked by the pins `-nr`/`-rn` decode like `-n` then `-r` and `-u` is
#     refused.
#
# NOT proved in this stage, stated plainly:
#   * `sort`'s FLOAT spellings and `-h` (d-F4-3c): `num_key` covers the integer
#     fragment of `parse::<f64>` (`-12`, `007`), not `1.5`/`1e3`, and nothing is
#     claimed for `-h`'s `human_size` key although the fold accepts `-h`. `-u`,
#     `-k` and `-t` are refused by the fold itself, so they are outside every law
#     by construction. The byte-level join of the sorted lines is the §1
#     `join_sep`/`echo_bytes` model, not restated here.
#   * `native_sort_file_stmt`'s numeric key (`__sh_num($a) <=> __sh_num($b)`) is
#     a different fold (the `sort FILE` shell-out, not the literal-pipeline fold
#     §7 models) and is not covered here.
#   * the general `comm -12` intersection law over two distinct sorted files —
#     needs ordered-membership invariants for the two-pointer walk (d-F4-4).
#   * diff's output beyond silence — d-F4-5b: the converse ("a change always

#     backtrack's cursors to prefix equality (a[0..i] == b[0..j]); the general
