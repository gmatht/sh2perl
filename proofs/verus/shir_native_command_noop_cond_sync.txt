# THE LAW.  The fold is the only one in shir_native_stmt.rs that rewrites a
# CONDITION into a constant.  It accepts `redirect(Call{builtin|exec,
# [Str "command", Array []]}, specs…)`, optionally behind one `!`, and writes
# `IrExpr::Bool(not_wrapped)`.  What it is really saying is "the redirects fail,
# so the command never runs": in bash the redirects are performed first, and
# `command` with no arguments would succeed (status 0) — it is the REDIRECT that
# fails.  An empty target (`<''`, `>''`) can never be opened, so that case is
# statically decided.
#   * status_law: given that every spec targets the empty string and there is at
#     least one spec, fold(c) == Some(not_wrapped) AND bash's status is 1 AND
#     fold(c) == Some(decided_truth(not_wrapped, 1)).  The fold is a shape match
#     (fold, §2); the shell side is run_status/decided_truth (§3), written from
#     the redirect-then-command order and never mentioning the fold.
#   * redirect_failure_dominates / no_specs_command_succeeds /
#     empty_target_makes_the_redirect_fail: the semantic side on its own.
#   * the_empty_target_is_what_the_law_needs: the same fold answer with no specs
#     at all has bash status 0 — the empty target is load-bearing, not decoration.
#   * refusals (each proved, and each merely CONSERVATIVE): a worded command
#     (worded_command_is_refused), another program (other_name_is_refused),
#     another launcher spelling (other_func_is_refused), a redirect body that is
#     not exactly one Call statement (block_inner_is_refused), a condition with no
#     redirect Call (a_non_redirect_cond_is_refused), and a double `!`
#     (only_one_not_is_stripped — the fold strips at most one Not).
#     refusal_is_conservative proves the point for the empty-target case: the
#     answer is already 1 whatever the words are, and the fold still declines.
#
# d3 (a RECORDED divergence, not fixed here; the fix is a source guard that
# requires every spec's target to be the empty string):
#   d3a `if command > /dev/null` — the redirect succeeds and `command` exits 0,
#       so bash's condition is TRUE; the fold writes false.  Pinned by
#       pin_the_fold_ignores_the_target and MEASURED with bash.
#   d3b `if ! command <$IN >$OUT` (the corpus' own lex-dot-in-var.sh shape) —
#       with openable files bash's `!` is FALSE; the fold writes true.  Pinned by
#       pin_a_dynamic_target_is_a_guess and measured with two temp files.
#   the_fold_never_inspects_the_specs: the fold fires on ANY spec sequence, which
#   is exactly the guard d3 needs and does not have.
#
# RESIDUE, stated not claimed: specs are modelled by TARGET only (the fold reads
# fd and mode not at all, so modelling them would prove nothing extra); `words`
# is modelled by its LENGTH (the fold calls `words.is_empty()` and never looks
# inside); `builtin` and `exec` are one Func::Direct (the fold treats them alike
# and both mean "run directly").  A `redirect` Call with ZERO specs is excluded
# by the law's `specs.len() > 0`: the parser emits a redirect Call only when a
# redirect was written, and the fold's zero-spec case is covered by d3's shape
# (a fold answer with no redirect at all), not by the law.
#
# Out of model: which fd a spec redirects (the fold ignores it), whether a
# non-empty literal target will open (d3), `command`'s own options handling, and
# the effect of the If's bodies (the fold only rewrites the condition).
