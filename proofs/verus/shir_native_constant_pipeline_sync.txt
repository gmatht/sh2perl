#
# THE LAW.  For a pipeline whose every stage is a word-free true/false exec,
# native_constant_pipeline replaces the statement with status_exec(last stage
# == "true").  Two independent definitions:
#   * the pass's side is `pass_decides`: the universal gate over the stages'
#     SYNTAX (every stage is one statement, an exec/builtin Call, true or false,
#     and has no words) plus a read of the LAST stage's NAME;
#   * the semantic side is stated over the stages' BEHAVIOURS (bytes written,
#     status exited), joined to the syntax only by `stage_spec` (the two
#     builtins write nothing and exit 0/1).
# fold_is_sound then proves: pass_decides == Some(b) ==> bash's pipeline status
# (the last stage's status) == b AND the pipeline's stdout is empty — so the
# rewrite keeps the status and loses no output.
#
# RESIDUE, stated not claimed: bash's rule is modelled as
# pipeline_status(sts) = sts.last() rather than as an inductive execution fold.
# An earlier draft carried the fold (consume each status, report the last) and
# the induction "fold == last"; Verus's per-function fuel made that induction
# expensive at rlimit 40, so the fold is the documented justification and the
# last-element rule is the model.  What is proved is the part a pass can get
# wrong: which stage the status comes from, and whether that stage's status is
# what its name says.
#
# d1 (a recorded divergence, not modelled away): the fold ignores
# `set -o pipefail`, under which `false | true` exits 1 while the fold writes
# status_exec(true).  The IR carries no pipefail state here, so there is no gate
# to prove; the generated test pin_pipefail_disagrees runs both bash forms and
# shows the disagreement.
